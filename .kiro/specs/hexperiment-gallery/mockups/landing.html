Is your model too good to be true?

Hexperiment is a Kiro power that catches data leaks in machine-learning code: test answers that sneak into training and fake a high score. Kiro’s agent then fixes them.

A leak makes a broken model look perfect.

A model learns from training rows, then gets graded on test rows it has never seen. A data leak lets information from the test rows slip into training. The model has seen the answers, so it aces the test and fails on real data.

It’s like a unit test that reads its expected value from the code it tests: it always passes and proves nothing. When an AI agent writes the training code, a leak is easy to miss. Nothing crashes. The score just goes up.

It scrambles the answers and watches what moves.

Hexperiment runs your training script twice. The second time, it scrambles only the test rows. Honest code never uses the test rows to train, so nothing in training should change. This is the canary test.

  1. Train normally

    Hexperiment records exactly what training produced.

  2. Scramble the test rows, train again

    Same script, same seed. Only the test rows are shuffled.

  3. Compare

    If any training row changed, the test rows leaked into training. In the hotel app, 95,309 of 95,457 changed.

Five ghosts it hunts.

Each check names the leak it found, so a failed run reads like a story. A model is approved only when a full run passes every check and reaches its target score.

The Doppelganger
The same rows sit in training and test.
The Possession
One column gives the answer away, like a status filled in after the booking ends.
The Peeking Spirit
Training saw the test rows. The canary test catches it.
The Prophet
Training uses rows from after the test period.
The Shapeshifter
Identical runs give different results, so nothing can be verified.

It lives inside Kiro.

Hexperiment installs as a Kiro power. Kiro’s agent gets the rules, the tools, and a loop that does not stop until the leak is gone.

Steering
Before it writes training code, the agent reads the rules: split first, no columns from the future, always end with an audit.
Save hook
Saving a training script runs a fast check and clears the old verdict, so an old approval stops counting once the code changes.
MCP tools
The agent can list apps, run the audit, read the verdict and its history, and ask what a ghost means.
Guardrails
The agent cannot edit the verdict, the model card, the thresholds or the data. It has to fix the cause.

Then it fixes the leak and checks again.

/workflow run exorcise hands an app to the ghost-hunter agent and repeats until the full audit approves it.

  1. Edit

    The ghost hunter changes the training code to remove the cause of each finding.

  2. Audit

    The full audit runs again, canary test included.

  3. Repeat

    Still rejected? It reads the new findings and tries again, up to five times.

  4. Hand back

    Approved, or out of tries: it stops and shows you the latest verdict.
